# Учебный модуль: состояние на 4 ноября 2026

Реализован первый этап — схема изолированной базы MySQL и серверный фундамент
подтверждения платежа. Ветка не меняет действующий сайт и ничего не списывает.

## Схема
- `lrn_users`: слушатели, email, отметка подтверждения.
- `lrn_courses`: каталог, цена в копейках, три календарных месяца, публикация.
- `lrn_lessons`: упорядоченные уроки и содержание.
- `lrn_materials`: метаданные, SHA-256, закрытый storage key вместо публичной ссылки.
- `lrn_orders`: снимок названия/цены/условий курса и версий согласий при покупке.
- `lrn_payments`: магазин, test-режим, idempotence key, связанный платёж ЮKassa.
- `lrn_access`: начало/конец, отзыв, первое открытие.
- `lrn_events`: уникальные события оплаты и будущих действий.
- `lrn_documents`: документальные снимки; чек и подписанный акт не подменяются.
- `lrn_mail_outbox`: очередь, попытки, блокировка обработки и результат доставки.
- `lrn_schema_migrations`: контроль версии и SHA-256 миграции.

Внешние ключи запрещают урок без курса, материал чужого урока и доступ не своему заказу.
Ничего не удаляется каскадно: финансовая история сохраняется.

## Подтверждение оплаты
`createPaymentVerifier({shopId,secretKey,testMode,store})` возвращает
`confirmPayment(paymentId)`. Он читает платёж через аутентифицированный GET API ЮKassa,
затем вызывает `store.fulfillPayment(payment,policy)`.
Проверяются ID, магазин, режим test, succeeded/paid, точная сумма/валюта,
metadata.order_id и время captured_at. Неизвестные платежи не создают заказы.
Создание платежа должно сначала сохранять заказ и idempotence_key, а затем
привязывать provider_payment_id. Этот обработчик НЕ подключён к публичному серверу.

Транзакция блокирует запись заказа/платежа, сохраняет оплату, доступ,
два документальных снимка и одно задание письма. Дубликат возвращает прежний
доступ и не меняет его срок. Ошибка любого INSERT откатывает все изменения.

## Срок
Три календарных месяца от captured_at по Томску, а не 90 дней и не со времени
отправки письма. В конце короткого месяца день ограничивается последним днём.
Пример: 31.01.2026 15:30 Томск → 30.04.2026 15:30 Томск.
Хранение в UTC. Окончание интервала исключено: при now >= ends_at доступ закрыт.
Отзыв закрывает доступ независимо от даты.

## Запуск миграции в тестовой среде
Сначала создать НОВУЮ пустую базу с `learning` в имени и отдельным пользователем.
НЕ использовать базу Concrete CMS `host1688282_concretetest` или действующую базу PracticAI.
Передать параметры из `learning/.env.example` через окружение процесса; скрипт не читает
секреты из репозитория. Пароль не передавать аргументом команды.

```sh
LEARNING_MIGRATE=1 node learning/migrate.js
```

DDL MySQL не транзакционный. Миграция использует advisory lock и restart-safe
CREATE TABLE IF NOT EXISTS; после частичного сбоя можно повторить. Отметка версии
появляется только после всего DDL. Применённую миграцию не редактировать.
Автоматического запуска миграций при старте сайта нет.

## Проверки
```sh
npm test
# На отдельной MySQL при заданных LEARNING_DB_*:
LEARNING_INTEGRATION=1 node --test tests/learning-mysql.integration.test.js
```
Без БД интеграционная проверка явно пропускается. GitHub workflow поднимает MySQL 5.7
в отдельном контейнере и проверяет миграцию, FK, пять параллельных подтверждений,
единственность документов/письма, полный rollback и успешную повторную попытку.

## Что ещё нужно реализовать до включения продаж
1. Редактор курсов/уроков, импорт согласованных материалов, личный кабинет.
2. Подтверждение email, одноразовый вход, сессии, серверная выдача защищённых материалов.
3. Создание заказов/платежей ЮKassa с ценой из БД, форма оплаты, webhook, сверка задержанных платежей.
4. Mail worker с backoff, одноразовая ссылка, журнал фактической отправки и первого открытия.
5. Полный/частичный возврат и правила отзыва доступа.
6. Утверждённые реквизиты продавца, шаблоны документов/акта и параметры фискализации.
7. Интеграционные испытания тестового магазина, резервная копия и согласованный запуск.

Секрет тестового магазина, SMTP и материалы пока не подключены. Реальные платежи
и письма не отправлялись. Данный этап не объявляется готовой платформой продаж.
