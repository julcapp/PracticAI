# Учебный модуль: состояние на 4 ноября 2026

Реализован первый этап — схема изолированной базы MySQL и серверный фундамент
подтверждения платежа. Ветка не меняет действующий сайт и ничего не списывает.

## Схема
- `lrn_users`: слушатели, email, отметка подтверждения.
- `lrn_courses`: каталог, цена в копейках, три календарных месяца, публикация.
- `lrn_lessons`: упорядоченные уроки и содержание.
- `lrn_materials`: метаданные, SHA-256, закрытый storage key вместо публичной ссылки.
- `lrn_orders`: снимок названия/цены/условий курса и версий согласий при покупке.
- `lrn_payments`: магазин, test-режим, idempotence key, связанный платёж ЮKassa.
- `lrn_access`: начало/конец, отзыв, первое открытие.
- `lrn_events`: уникальные события оплаты и будущих действий.
- `lrn_documents`: документальные снимки; чек и подписанный акт не подменяются.
- `lrn_mail_outbox`: очередь, попытки, блокировка обработки и результат доставки.
- `lrn_schema_migrations`: контроль версии и SHA-256 миграции.

Внешние ключи запрещают урок без курса, материал чужого урока и доступ не своему заказу.
Ничего не удаляется каскадно: финансовая история сохраняется.

## Подтверждение оплаты
`createPaymentVerifier({shopId,secretKey,testMode,store})` возвращает
`confirmPayment(paymentId)`. Он читает платёж через аутентифицированный GET API ЮKassa,
затем вызывает `store.fulfillPayment(payment,policy)`.
Проверяются ID, магазин, режим test, succeeded/paid, точная сумма/валюта,
metadata.order_id и время captured_at. Неизвестные платежи не создают заказы.
Создание платежа должно сначала сохранять заказ и idempotence_key, а затем
привязывать provider_payment_id. Этот обработчик НЕ подключён к публичному серверу.

Транзакция блокирует запись заказа/платежа, сохраняет оплату, доступ,
два документальных снимка и одно задание письма. Дубликат возвращает прежний
доступ и не меняет его срок. Ошибка любого INSERT откатывает все изменения.

## Срок
Три календарных месяца от captured_at по Томску, а не 90 дней и не со времени
отправки письма. В конце короткого месяца день ограничивается последним днём.
Пример: 31.01.2026 15:30 Томск → 30.04.2026 15:30 Томск.
Хранение в UTC. Окончание интервала исключено: при now >= ends_at доступ закрыт.
Отзыв закрывает доступ независимо от даты.

## Запуск миграции в тестовой среде
Сначала создать НОВУЮ пустую базу с `learning` в имени и отдельным пользователем.
НЕ использовать базу Concrete CMS `host1688282_concretetest` или действующую базу PracticAI.
Передать параметры из `learning/.env.example` через окружение процесса; скрипт не читает
секреты из репозитория. Пароль не передавать аргументом команды.

```sh
LEARNING_MIGRATE=1 node learning/migrate.js
```

DDL MySQL не транзакционный. Миграция использует advisory lock и restart-safe
CREATE TABLE IF NOT EXISTS; после частичного сбоя можно повторить. Отметка версии
появляется только после всего DDL. Применённую миграцию не редактировать.
Автоматического запуска миграций при старте сайта нет.

## Проверки
```sh
npm test
# На отдельной MySQL при заданных LEARNING_DB_*:
LEARNING_INTEGRATION=1 node --test tests/learning-mysql.integration.test.js
```
Без БД интеграционная проверка явно пропускается. GitHub workflow поднимает MySQL 5.7
в отдельном контейнере и проверяет миграцию, FK, пять параллельных подтверждений,
единственность документов/письма, полный rollback и успешную повторную попытку.

## Кабинет и контакты — дополнение
Миграция `002_profile.sql` добавляет телефон, Telegram, ссылку MAX, WhatsApp,
предпочтительный канал и отдельные отметки подтверждения. Телефон обязателен
при сохранении профиля, в международном формате + и 8–15 цифр; email не меняется
через эту форму. Мессенджеры необязательны. Значение предпочтительного канала
проверяется против заполненных контактов. Рекламные согласия этой формой не выдаются.

`createPortalStore(pool)` хранит и читает профиль; изменение контакта сбрасывает
его подтверждение, сохранение неизменённого контакта сохраняет отметку.
`createPortalRouter({store,authenticate,origin})` требует проверенный сервером
`req.learningUser.id`, защищает PUT проверкой Origin и запрещает кэширование.
Без middleware сессий маршруты НЕ подключать. ID из body/query/header не используется.

`learning/public/account.html`, `.css`, `.js` — адаптивный экран профиля,
списка курсов и заказов. Уроки и документы пока не открываются с него.
Авторизация по одноразовой ссылке и размещение кабинета в тестовой среде ещё
предстоят; существующий `server.js` не изменён и модуль не опубликован на домене.

### Основа входа (следующий этап)
`auth.js` и миграция 003 добавляют одноразовые ссылки (15 минут) и сессии
(7 суток). В БД записываются только SHA-256 хеши случайных 256-битных
секретов. Обмен ссылки на сессию выполняется одной транзакцией с блокировкой;
повторный или просроченный токен отвергается. Секрет ссылки передаётся во
фрагменте URL. Пока нет публичных маршрутов входа, отправки писем, cookie и
страницы обмена ссылки: этот модуль сам по себе вход на сайт не включает.
Перед подключением нужны ограничение частоты запросов, одинаковый ответ для
существующего/неизвестного email, Secure/HttpOnly/SameSite cookie, выход,
очистка истёкших записей и интеграционные проверки реальной БД.

### Подключение входа в изолированном приложении
`createLearningApp({pool,origin,sendLink})` соединяет кабинет с реальной
серверной сессией, страницей `/learning/login.html` и POST-маршрутами
`/api/learning/auth/request`, `/redeem`, `/logout`. Cookie имеет префикс
`__Host-`, Secure, HttpOnly, SameSite=Strict; срок сессии 7 суток. Ограничение
20 запросов за 15 минут на IP рассчитано на один процесс; при нескольких
процессах потребуется общее хранилище ограничений. За reverse proxy нельзя
включать произвольное доверие X-Forwarded-For.

`createLinkSender` из `mail.js` принимает настроенный SMTP transport и отдельного
отправителя PracticAI. SMTP-секреты не записываются в репозиторий. Письмо
отправляется по явному запросу пользователя; неизвестный адрес получает тот же
ответ. Доставка сейчас непосредственная, без фоновой очереди и повторов.
Ошибки отмечаются callback без адреса, ссылки и токена. GET страницы не
использует ссылку: пользователь подтверждает вход кнопкой, секрет удаляется
из адресной строки. Уроки/материалы пока не подключены.

Перед первым применением миграции 003 используется явный ASCII charset
для FK user_id, совпадающий с lrn_users.id. На рабочих БД она ещё не применялась.
Необходимы проверка MySQL 5.7 в CI, тест доставки с отдельным почтовым ящиком
PracticAI, удаление истёкших сессий и тестовое развёртывание HTTPS. Основной
server.js не меняется; приложение автоматически не запускается.

### Уроки
В отдельном приложении подключены GET `/api/learning/courses/:courseId/lessons`
и `/:lessonId`, страница `/learning/course.html?id=…` и переход из кабинета.
SQL выдаёт только опубликованные уроки при наличии оплаченного заказа и
активного доступа текущего пользователя. Начало включительно, окончание
исключительно; время берётся из UTC на сервере MySQL. Отозванный доступ и
заказ с возвратом не допускают чтения. При повторных покупках достаточно
хотя бы одного действующего оплаченного доступа. Содержание передаётся как
обычный текст и отображается через textContent, без выполнения HTML.
Идентификаторы пользователей берутся только из серверной сессии.

Файлы, презентации и видео пока не выдаются. Их storage_key нельзя помещать
в публичный каталог: следующий этап требует закрытого хранилища и проверки
доступа перед каждым скачиванием. Уже полученный текст браузер пользователя
может сохранить; истечение доступа блокирует последующие запросы.
