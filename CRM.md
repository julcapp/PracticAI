# Объединение PracticAI и образовательного направления

- `/` — прежняя главная PracticAI с блоком и ссылкой на образовательное направление. Сервер подключает `site-enhancements.js` к оригинальному `public/index.html` при выдаче главной страницы.
- `/education.html` — образовательные направления ООО «Цифрономика», каталог предварительных тем и сведения об организации.
- `/admin` — CRM. HTTP Basic вход с `ADMIN_USER` и `ADMIN_PASSWORD` (не менее 16 символов) из окружения. Без них CRM возвращает 503.
- CRM: тексты главной и образовательной страницы; произвольные дополнительные разделы (главная или образование), порядок и статус публикации; обращения и статусы.
- CRM также управляет главным изображением и изображениями дополнительных блоков. Редактор блоков позволяет выбрать положение изображения, сохранить черновик и посмотреть вид блока на ширине компьютера и телефона до публикации. Уже существующие статические блоки сайта остаются в исходной разметке.
- Загрузка через защищённый маршрут `POST /media/upload`: PNG, JPEG или WebP до 3 МБ. Файлы сохраняются в каталоге `media/` приложения и доступны для чтения по `/media/<id>.<расширение>`. Этот каталог необходимо сохранять при развёртывании и резервном копировании.
- Новые таблицы `site_content`, `site_texts` создаются сервером при первом обращении, если пользователь БД имеет право CREATE TABLE. Для ручной установки есть `migrations/002_site_content.sql`.
- Старый `GET /api/contact`, который возвращал заявки без авторизации, теперь закрыт. Получение и обновление обращений работает только через `/api/admin/contacts`.
- Форма на главной вместо фиктивного подтверждения отправляет `POST /api/contact`; требуется подтвердить окончательную политику обработки персональных данных и текст согласия до публичного запуска.
- Для продакшн-развёртывания добавить `ADMIN_PASSWORD` как секрет GitHub Actions и прокинуть его в `.env` на сервере или установить `.env` вручную **после** каждого деплоя. Не хранить пароль в репозитории.
- ЮKassa: интеграция не включена. После предоставления доступа отдельно реализовать создание платежа сервером, webhook, сверку статусов и отображение оплаты только для утверждённых программ.

## Консультант и запрос на запись

- На главной и странице образования расположен консультант с быстрым выбором направления и отдельной формой запроса на запись. Форма сохраняет обращение в существующей CRM и отправляет обычное уведомление. Заявка не означает подтверждённое зачисление.
- `POST /api/assistant` использует только краткие подтверждённые сведения и опубликованные блоки. При установленном `OPENAI_API_KEY` отвечает через серверный Responses API; ключ не попадает в браузер. Без ключа работает ограниченный справочный режим. Ответы не заменяют утверждённые условия программ.
- В GitHub Actions добавьте `OPENAI_API_KEY` в Secrets репозитория для включения AI. После этого повторите развёртывание. Не передавайте ключ в чат и не храните в исходниках.
- Для настоящей записи нужны утверждённые карточки программ, даты, условия, наличие мест и процедура подтверждения менеджером. До их публикации собираются запросы на запись.


## Консультант: сценарии ответов

В CRM откройте вкладку «Консультант». Здесь задаются код, вопрос, ключевые фразы (по одной на строку), ответ, направление, приоритет и статус. Включённые сценарии отвечают на сайте после сохранения. Выключенные и удалённые исключаются из ответов. Первичные сценарии создаются один раз и не восстанавливаются при перезапуске.

«Проверить ответ» использует текущие поля формы, включая несохранённый или выключенный сценарий. Проверка ничего не публикует. При нескольких совпадениях предпочтение у направления, затем у приоритета, затем у самой длинной ключевой фразы. Текст отображается без выполнения HTML.

Виджет сохраняет выбранное направление при уточняющих вопросах и подставляет его в форму заявки. Личные данные вводятся только в отдельной форме с согласием; в историю чата они не добавляются. Успех показывается после получения номера сохранённой заявки. Ошибка сохраняет заполненные поля. Неизвестные условия уточняет менеджер.

Внешние AI-запросы отключены: ключ не требуется. База MySQL необходима для работы сценариев. После выкладки проверьте /api/admin/diagnostics (assistant_scenarios: ok) и вкладку «Консультант». `npm test` проверяет выбор ответов, API, начальное заполнение базы, CRM и виджет; SQL в тестах заменён тестовым хранилищем, поэтому наличие реальных таблиц проверяется дополнительно на сервере.


## Полноценная CMS

Адрес `/admin/cms` использует тот же вход администратора, что CRM. Из CRM доступна ссылка «Управление сайтом (CMS)». Прежний редактор блоков доступен только для просмотра архива: после первичного переноса новые изменения сайта вносятся в CMS.

Слева выберите страницу, курс, экспертов или общие настройки. Для страницы редактируются все текстовые фрагменты, ссылки и изображения исходных разделов. Исходные заголовки могут быть разделены на несколько полей, чтобы сохранить оформление. Меню и условия бухгалтерского курса редактируйте в одноимённых общих документах: они имеют приоритет над локальными полями страницы. Положение шапки и подвала фиксировано, их содержимое и видимость редактируются. Между ними можно перемещать содержательные разделы.

Можно создавать новые страницы `/pages/адрес`, добавлять текст, изображения, карточки, вопросы и ответы, кнопки; менять порядок и видимость. Новую страницу добавьте в меню через общий документ. Шесть карточек экспертов сохранены; их можно дополнить, переместить и скрыть.

«Сохранить черновик» не меняет сайт. «Предпросмотр» показывает текущие поля страницы, не сохраняя их; режим телефона имеет ширину390px. «Опубликовать» сохраняет несохранённые поля и публикует редакцию. История хранит предыдущие опубликованные редакции. «Восстановить в черновик» не изменяет сайт до следующей публикации. При конфликте версий текст остаётся на экране: скопируйте его перед загрузкой актуальной версии. Цена, время и программа курса публикуются отдельно от общих страниц.

Материалы: PNG/JPEG/WebP до3МБ, PDF до10МБ. Скопируйте адрес загруженного файла в поле изображения или ссылки. PDF скачивается как вложение, файлы не исполняются. Новые файлы не заменяют старые; это сохраняет ссылки в прошлых редакциях.

### Хранение и восстановление

Содержимое хранится в MySQL: `cms_documents` (черновики/публикации), `cms_revisions` (история). `cms_backups` содержит первичный снимок прежних `site_texts` и `site_content`. Импорт не меняет и не удаляет исходные таблицы, обращения и сценарии. `cms_setup` предотвращает повторное заполнение. Нельзя удалять эти таблицы при очередной выкладке кода. Для полного переноса сохраните данные этих таблиц и каталог `media/` отдельно от GitHub; фото и PDF пользователя в Git не попадают.

Маршрутизация Hostland: `.htaccess` в `htdocs/www` передаёт три существующие страницы внутренним маршрутам `/cms-render/main`, `/cms-render/education`, `/cms-render/accountants`; внешние URL сохраняются. Существующий файл правил копируется перед первым обновлением в `/practicai.ru/projects/htaccess-before-cms.conf`, вне публичной папки. При восстановлении старой маршрутизации этот файл можно вернуть по FTP как `htdocs/www/.htaccess`; база CMS сохраняется. Предыдущие версии опубликованного содержимого восстанавливаются через CMS, без FTP.

Тесты `npm test` проверяют модель, безопасность, историю, публикацию, серверный вывод и редактор. SQL в тестах заменён тестовым адаптером; реальные таблицы и HTTP проверяет workflow после публикации. Главная и курс должны содержать `data-practicai-cms="1"`. Административные маршруты без входа возвращают401.
